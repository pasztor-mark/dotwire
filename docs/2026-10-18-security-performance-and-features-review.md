**dotwire security, correctness, and efficiency review — 18 October 2026**

Reviewed checkout: `40d5dfa` (`v0.1`). Source files were not changed. Scope: server authorization, realtime fanout, persistence, erasure, audit, webhooks, schema, deployment configuration, both host SDKs, browser client, React hooks, and dependency advisories. Product exclusions and the read/write, AOT, encryption, and ephemeral-traffic contracts were treated as binding.

Priority meanings: **P1** should be fixed before relying on the affected guarantee; **P2** is a material correctness or efficiency issue; **P3** is lower urgency. “Reproduced” means a local probe exercised the relevant implementation or runtime behavior. “Source-traced” means the failure follows from the code and documented dependencies, but the complete distributed scenario was not executed.

**Findings, in priority order**

1. **P1 — Compose publishes an unauthenticated broker outside the container network.** [compose.yaml:82](../compose.yaml#L82), [compose.yaml:89](../compose.yaml#L89). NATS starts with JetStream and monitoring but no authentication, and both ports are published on all host interfaces. Anyone who can reach 4222 can bypass dotwire's JWT and membership checks at the broker boundary: subscribe to ciphertext/metadata, publish forged audit or revocation events, or invoke JetStream administration. Encryption does not protect stream availability or audit provenance. Remove host publication for service-only ports; use explicit loopback bindings for development and authenticated, authorized NATS connections where network access is needed. This is configuration/source verified, not a claim that this machine is presently exposed. [NATS authentication documentation](https://docs.nats.io/learn/security/authentication-basics) confirms that an unconfigured server admits connections without credentials.

2. **P1 — Live room access survives token expiry.** [Program.cs:170](../dotwire/Program.cs#L170), [Events.cs:47](../dotwire/Api/Events.cs#L47). The hub does not enable `CloseOnAuthenticationExpiration`; the custom SSE endpoint only uses request cancellation and never schedules expiry. A valid short-lived token can establish a connection that keeps receiving room content after expiration, undermining AUTH.md's TTL boundary for a stolen token. The local runtime probe confirmed the hub option defaults to false. Enable expiry closure for SignalR and link SSE lifetime to the validated ticket's expiry, then reconnect with a fresh token. [Microsoft documents this default](https://learn.microsoft.com/en-us/aspnet/core/signalr/authn-and-authz?view=aspnetcore-10.0).

3. **P1 — Audit redelivery can permanently discard uncommitted events.** [AuditWriterService.cs:104](../dotwire/Nats/AuditWriterService.cs#L104), [AuditWriterService.cs:154](../dotwire/Nats/AuditWriterService.cs#L154). The writer assumes that every stream sequence below its database tail was committed. Example: it fetches 1–200, fails before commit, retries after one second, fetches and commits 201–400, then receives 1–200 after their ack timeout. Those events are skipped by `streamSeq <= tailStreamSeq` and then acknowledged. The resulting chain can verify while omitting actions. A Postgres advisory lock only prevents concurrent writers; it does not guarantee delivery order after a failed fetch/commit. Preserve/retry the failed batch before advancing and enforce a contiguous durable cursor, or deduplicate by actual persisted event identity with an explicit ordering strategy. The existing restart test starts after successful commit/ack and does not exercise this failure. Source-traced; [NATS redelivery timing](https://docs.nats.io/learn/jetstream/acknowledgment) and [pending-message limits](https://docs.nats.io/learn/jetstream/pull-consumers) permit later deliveries while the earlier batch awaits redelivery.

4. **P1 — Admin changes can commit without an audit record, and audit failure skips live revocation.** [Admin.cs:52](../dotwire/Api/Admin.cs#L52), [Admin.cs:238](../dotwire/Api/Admin.cs#L238), [Admin.cs:250](../dotwire/Api/Admin.cs#L250). Role/membership/retention mutations commit before the separate audit publish. An audit failure or request cancellation leaves the mutation applied without a durable audit record; returning 503 does not undo it or force the caller to retry. Membership removal also returns before its revocation broadcast if audit fails, so an existing subscriber keeps reading despite the deleted membership. Role deletion has the same ordering. Separate authorization invalidation from audit delivery success and make admin mutations recoverably coupled to durable audit intent using the existing infrastructure. Source-traced.

5. **P1 — Concurrent persistence can restore a redacted message.** [0006_redaction.sql:25](../dotwire/Migrations/0006_redaction.sql#L25), [0006_redaction.sql:48](../dotwire/Migrations/0006_redaction.sql#L48). The tombstone trigger handles sequential arrival but has no common lock with redaction. A writer can pass the trigger and insert an uncommitted message; redaction then commits a tombstone and deletes zero visible rows; the writer subsequently commits the content. Redaction can return success with content still present in history. Serialize insertion and redaction for the same room/sequence with a shared database locking protocol, and test both transaction interleavings against Timescale. This is a source-traced MVCC race, not a reproduced database test. [PostgreSQL's isolation documentation](https://www.postgresql.org/docs/current/transaction-iso.html) explains the visibility rules involved.

6. **P1 — An overflowing SSE channel silently loses messages instead of disconnecting.** [RoomInterestManager.cs:146](../dotwire/Realtime/RoomInterestManager.cs#L146), [RoomInterestManager.cs:182](../dotwire/Realtime/RoomInterestManager.cs#L182). `DropWrite` makes `TryWrite` report success even when it discards the new item, so the “disconnect laggard” branch never runs. A later delivered sequence advances the resume cursor past a silently missing message. **Reproduced on the actual manager:** capacity 1, publish sequences 1 and 2, drain → sequence 1 only, reader completion false. Use a full mode where a nonblocking `TryWrite` can detect overflow, then close/cancel the connection. The same mistake suppresses the postsend queue's advertised overflow warning at [PostSendWebhookService.cs:29](../dotwire/Nats/PostSendWebhookService.cs#L29). [Runtime implementation](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Threading.Channels/src/System/Threading/Channels/BoundedChannel.cs) confirms these semantics.

7. **P1 — Browser reconnect replay skips older messages when live traffic advances its cursor.** [client.ts:214](../packages/client/src/client.ts#L214). Each history page reads `state.lastSeq`, which is also advanced by live delivery. **Reproduced using the actual client and existing fake connection:** start at 10, receive live 20 while fetching history 11–12, then the next request uses `afterSeq=20`, skipping 13–19. Freeze the pre-reconnect starting point and maintain a replay cursor advanced only by replayed rows; merge live messages independently with deduplication.

8. **P1 — Gap-fill cannot recover messages that were accepted before subscription but have not reached Postgres.** [Events.cs:79](../dotwire/Api/Events.cs#L79), [Messages.cs:266](../dotwire/Api/Messages.cs#L266). Replay reads only Postgres. A message can receive its JetStream ack while the subscriber is offline, miss the new core subscription, and still be absent from history at reconnect. Empty history ends replay; a subsequent live message moves the client beyond the missing message. This is especially visible during database outages or writer backlog, both explicitly allowed by the architecture. Establish a persisted/replay high-water boundary and recover the unpersisted tail from JetStream, with redaction checks, or use another bounded retry protocol that can prove replay completeness. Source-traced.

9. **P1 — SSE replay continues disclosing history after membership revocation.** [Events.cs:77](../dotwire/Api/Events.cs#L77), [RoomInterestManager.cs:234](../dotwire/Realtime/RoomInterestManager.cs#L234). Revocation completes the live channel, but replay does not inspect that channel until every history page has been sent. Its cancellation token is only `RequestAborted`. A user requesting a large replay can keep receiving history after removal. Give each SSE registration a cancellation source that revocation triggers and use it for database replay and HTTP writes; discard queued content when access ends. Source-traced.

10. **P2 — Stop-typing notifications bypass every server-side throttle.** [RoomHub.cs:86](../dotwire/Realtime/RoomHub.cs#L86), [HubRateLimitFilter.cs:33](../dotwire/Realtime/HubRateLimitFilter.cs#L33). The cooldown applies only when `isTyping=true`, while the hub rate limiter excludes Typing altogether. A member can issue repeated `Typing(roomId,false)` calls and amplify them to every room subscriber. **Reproduced on RoomHub with a counting NATS test double:** 1,000 immediate false calls published 1,000 events; 1,000 true calls published one. Bound both transitions and suppress repeated unchanged state.

11. **P2 — A slow SignalR receiver stalls subsequent room fanout, including SSE.** [RoomInterestManager.cs:277](../dotwire/Realtime/RoomInterestManager.cs#L277). The one room subscription loop awaits group send completion before reading the next NATS message or forwarding to SSE. The registered default lifetime manager waits for all pending connection writes. A backpressured socket therefore delays later messages for every receiver until it drains or times out; the promised independent bounded queues/disconnect policy is not implemented. Preserve shared serialization while isolating per-connection backpressure, and test one stalled socket alongside healthy sockets and SSE. Source-traced against [the .NET 10 lifetime manager](https://raw.githubusercontent.com/dotnet/aspnetcore/v10.0.10/src/SignalR/server/Core/src/DefaultHubLifetimeManager.cs).

12. **P2 — DSAR exports buffer the complete JSON response.** [Admin.cs:568](../dotwire/Api/Admin.cs#L568), [Admin.cs:641](../dotwire/Api/Admin.cs#L641). Rows are read incrementally, but the stream-backed `Utf8JsonWriter` is flushed only once at the end. Its internal buffer grows with all exported content, so large or concurrent exports can exhaust memory. **Runtime reproduction:** 2,048 synthetic 1 KiB strings produced 2,103,297 pending bytes and zero committed bytes before the final flush. Flush asynchronously at a bounded byte/row threshold and honor cancellation throughout.

13. **P2 — Redaction's room identifier is not checked against the JetStream message being erased.** [Admin.cs:416](../dotwire/Api/Admin.cs#L416), [Admin.cs:433](../dotwire/Api/Admin.cs#L433). Postgres deletion is scoped by room and sequence, but JetStream deletion uses only the global stream sequence. Supplying room A with a sequence belonging to room B deletes B's broker copy while recording a tombstone, audit event, and retraction for A. This is an integrity/accidental erasure bug in an admin-only operation, not a privilege escalation. Resolve and validate the stream subject/room before destructive steps, including the not-yet-persisted case. Source-traced.

14. **P2 — Disposed browser room handles remain strongly referenced.** [client.ts:268](../packages/client/src/client.ts#L268), [room.ts:222](../packages/client/src/room.ts#L222), [hooks.ts:89](../packages/react/src/hooks.ts#L89). `client.room()` adds every handle to `activeRoomHandles`; handle disposal never removes it. React cleanup deliberately avoids disposal to preserve shared subscriptions, retaining the handle and its cleanup closures for the provider's lifetime. **Reproduced:** 1,000 `room().dispose()` calls leave 1,000 handles in the set. Add a cleanup/unregister lifecycle independent of the shared room subscription.

15. **P2 — The TypeScript host send handler turns a successful send into an error when the local postsend hook fails.** [packages/host/src/client.ts:298](../packages/host/src/client.ts#L298), [packages/host/src/client.ts:473](../packages/host/src/client.ts#L473). `sendAsUser` throws a `PostSendError` carrying the accepted ack, but `handleClientSendCore` handles only presend/API errors and rethrows it. A normal host error boundary produces a failed request even though the message was stored; user retry duplicates it. The .NET handler already handles this correctly at [DotwireHostClient.Webhooks.cs:44](../Dotwire.Host/DotwireHostClient.Webhooks.cs#L44). Mirror that behavior in TypeScript. Source-traced.

16. **P2 — React pagination can merge the previous room's messages into the current room.** [hooks.ts:102](../packages/react/src/hooks.ts#L102). `loadOlder` awaits an uncancelled history request and dispatches its result without checking that the hook still represents the same room/client. Switching rooms during the request resets state, but the old response subsequently adds old-room messages into new-room state. This is UI isolation/correctness, not a server authorization bypass. Cancel outdated requests or check an effect-generation/room token before dispatch. Source-traced.

**Further efficiency and contract gaps**

- [AuditWriterService.cs:172](../dotwire/Nats/AuditWriterService.cs#L172): audit batches execute one awaited SQL round trip per row. Use an actual batched/multi-row insert while preserving the single writer and exact chain order.
- [SigningKeyRing.cs:94](../dotwire/Auth/SigningKeyRing.cs#L94): refresh performs synchronous HTTP under a global lock. On cache expiry, concurrent authentication requests can all block behind a slow JWKS fetch. Refresh asynchronously in the background with one in-flight request and an explicit last-good-key policy.
- [reducers.ts:43](../packages/react/src/reducers.ts#L43): each new message reconstructs a map and sorts the entire accumulated history. Memory is unbounded for an indefinitely mounted busy room. Use incremental insertion and a configurable retention/window policy in the hook.
- [PostSendWebhookService.cs:51](../dotwire/Nats/PostSendWebhookService.cs#L51): one worker serializes every webhook request and its retry sleeps. A slow endpoint creates queue buildup across unrelated rooms. If this is material for a host, add bounded delivery concurrency and observable queue/drop counters.
- [Program.cs:170](../dotwire/Program.cs#L170): server transport options allow SignalR SSE and long polling, despite the WebSockets-only contract. The probe confirmed all three default transports. Restrict server transports explicitly; the SDK's default alone does not enforce the deployment contract.
- [0006_redaction.sql:13](../dotwire/Migrations/0006_redaction.sql#L13): the compliance tombstone table has revoked mutation grants but lacks the guard triggers required by AGENTS.md. This is defense-in-depth and contract drift; normal runtime-role update/delete is already denied.
- [RoomInterestManager.cs:249](../dotwire/Realtime/RoomInterestManager.cs#L249): subscription registration starts NATS loops in background tasks and returns before readiness. Tests mask this with delays. The join/replay boundary needs an explicit readiness guarantee to avoid losing messages sent immediately after Subscribe completes.

**Optional features**

The requested **gpt-6-luna / high** subagent surveyed implemented features and recommended reactions, shared pins, personal bookmarks, and threaded replies. I would also consider idempotent sends before the larger UI-facing additions. Read receipts are a documented but unimplemented extension, so they should be tracked as completing that contract.

All proposed flag names below are new design suggestions. Use independent server-enforced `Dotwire:Features:<Name>:Enabled` flags, **default false**, consistent across nodes. A flag controls the feature's API and event delivery; UI hiding alone is insufficient. Disabling does not silently delete stored data. Authentication, encryption, authorization, and existing audit requirements remain enforced. Every member-facing endpoint/event needs parity in both host SDKs and the client SDK, with React support where relevant.

| Suggested order | Feature / flag | Value and effort | Disable behavior and constraints |
|---|---|---|---|
| 1 | Idempotent sends / `IdempotentSends` | Safe retries after ambiguous acknowledgements; medium design effort. Parent review addition. | Reject requests that explicitly require idempotency while off. When enabled, scope keys to sender and room, bind them to the request, define a retry window and stable ack, and preserve JetStream-first acceptance. |
| 2 | Emoji reactions / `Reactions` | Common embedded-chat interaction; medium effort. Luna recommendation. | Block mutations and hide aggregates/events while off; retain rows. Bound allowed values/counts and include room membership, erasure, retention, and export semantics. |
| 3 | Shared pins / `Pins` | Important messages remain easy to find; medium effort. Luna recommendation. | Block pin operations/listing while off; retain references. Explicit host policy for who may pin, ids-only auditing, and redaction/retention cleanup. |
| 4 | Ephemeral read receipts / `ReadReceipts` | Hosts can show “seen up to sequence”; small-to-medium effort. Completion of the documented ephemeral contract. | Stop publication and delivery while off; clear transient state. NATS core only, throttled/coalesced, no persistence or ack-path participation, and no durable unread-count promise. |
| 5 | Personal bookmarks / `Bookmarks` | Private saved-message references; medium effort. Luna recommendation. | Disable reads/mutations while off; preserve records. Key by host-owned `sub`, create no user directory, require current membership for content access, and cover DSAR/redaction/retention. |
| 6 | Replies/threads / `Threads` | Adds conversation structure; large effort. Luna recommendation. | Reject new parent references while off, but retain and return existing reply metadata so stored conversations remain intelligible. Validate same-room parent references and update both durable and live wire formats. |

The implementation seams are [message routes and DTOs](../dotwire/Api/Messages.cs#L140), [room hub methods](../dotwire/Realtime/RoomHub.cs#L26), [browser room handles](../packages/client/src/room.ts#L15), and [React hooks](../packages/react/src/hooks.ts#L58). These are proposals, not implemented features. Resolve the P1 correctness and access-control issues before expanding these surfaces.
